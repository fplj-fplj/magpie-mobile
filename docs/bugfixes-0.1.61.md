# 0.1.61 会话与编辑交互修复

## 确认的问题与修改

插件详情原先仅按 `plugin.spec` 记住初始参数 A，原生成功保存 B 后没有推进基线，继续在同一详情保存 C 会误报“参数已被其他入口修改”。现在直接观察该笔已接受写入的 VM 状态，等核心完成且权威参数等于提交值后才推进基线，不依赖 Compose 是否曾绘制 busy 帧。已知失败保留草稿与旧基线；未知结果等待只读核对；真正的外部 D 不会被当成当前草稿 C 的保存结果。

聊天页在高度低于 520 dp 或键盘显示时隐藏整组会话操作，横屏手机因而无法新建、切换历史、读更早记录或回最新；达到上下文上限时也缺少新建入口。紧凑布局改为模型选择器同排的会话菜单，菜单展开时保持锚点稳定，入口仍遵循既有忙碌状态与提供商写入限制，不要求网关连接才能使用本机历史。

网关密钥原先在排队后的 IO 中读取全局管理客户端，缺少完整连接轮次、取消与并发保护；旧请求可能在重连后操作替代连接，迟到结果仍可写入明文状态或剪贴板。现在在调用线程捕获 `ProviderSessionKey(owner, epoch)` 与私有管理凭据，HTTP 发送前、读取中及接收完成时核对身份，断开主动取消实际 Socket。创建内部的 GET→POST 和多字段限制保存均使用同一捕获连接，每一步核对有效性。页面按钮携带所绘制轮次，旧限制保存回调不能在新连接已 attach 后写入替代核心；Dashboard 在 effect 执行前也过滤旧轮次状态。

密钥 VM 绑定完整轮次并串行处理请求，重连清空明文、列表、提示及本地编辑草稿。写入异常后要求先显式刷新列表核对，再继续编辑，不自动重放 POST；普通列表永远剥离 secret，仅明确生成／复制可取得明文。模型／别名空输入仍按原说明“不修改”，服务档允许清空。保留原有暖纸色、RikkaHub 页面结构、霞鹜文楷屏幕阅读版与品牌 Poppins。

首轮真实 HTTP 400 页面回归进一步发现共享取消桥接器的错误：内部 `coroutineScope` 因业务异常失败时，watcher 误将其当作调用方取消，导致同一 lease 失效，插件 VM 无法清除明确失败的 pending。现改为进入内部作用域前捕获调用方上下文；业务失败保留原异常分类与可用连接，外部取消仍主动关闭 Socket。新增真实插件 controller／lease／HTTP 用例，覆盖 HTTP 400 后只读与明确再次保存、丢失 POST 响应仍为 unknown 且不重放，以及外部取消 headers 前／body 中途关闭实际连接。

版本为 `0.1.61-session-editor-fixes`、versionCode 62，备份 appVersion `0.1.61`；核心保持 `0.1.3781-androidhost.2`。

## 验证设计与状态

本地仅源码、接口、资源与空白检查，不运行 Gradle、Kotlin/JVM、Go 或 Android 编译及运行测试。所有编译和执行交由 GitHub Actions；同一源码的完整 Validation 与签名候选成功且实际报告／产物核对后，才触发正式发布。当前尚未把本轮候选发布到 Release。

新增密钥真实 HTTP 测试覆盖排队前切换同 owner 新 epoch／替代 owner、创建预读 GET 后阻止旧 POST、headers 前／body 中途的实际 Socket 取消、一次性正常请求和禁止重放；VM 用例覆盖串行、迟到结果、明文清理、旧 UI 回调、部分失败及明确只读核对。插件基线新增独立状态确认用例，并使用真实 Panel／VM／lease／HTTP 验证同详情 A→B→C、外部更新阻止草稿覆盖、HTTP 400 后显式重试。

新增 Android 聊天回归使用真实横屏／输入法、Compose、ViewModel 与内存 Room，验证离线新建／历史、26 轮记录分页往返、40 轮上下文上限时仍可新建且保留旧记录、键盘菜单重读不丢草稿。密钥页面另检查重连关闭旧限制弹窗、在新读取完成后执行旧 OnClick 仍零写入，以及断开后页面明文和名称草稿不恢复。

完整验收继续保留 JVM、两种实际 Go 核心、参数转发、目录 RPC/TLS、官方／社区三类插件、MCP／Hooks／SSE、race 和 API 35 x86_64 Android 综合用例。ARM64 仅核对正式包签名及载荷，不能表述为真机运行通过。实际数量、run、artifact、SHA 和正式发布结果待云端完成后独立核对并补录。
