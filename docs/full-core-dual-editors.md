# 完整 CLI 核心与双编辑入口

用户要求改用官方完整 CLI/TUI 路线，增加外部编辑与原生编辑，并以 RikkaHub 为原生提供商页参考。这里将“TY”理解为 TUI/CLI，将“外部编辑”实现为在手机浏览器打开官方管理网页；调用其他文件编辑 App 不属于本轮实现。

## 核心路线

旧包不是官方发布的独立 mobile 产品，而是官方 v0.1.3781 源码加本项目补丁，以 `nogui,mobile` 构建。很多功能缺失来自管理 API 白名单，以及部分原生页面只管理本机示例。

新 APK 构建标签为 `nogui,androidhost`，版本 `0.1.3781-androidhost.2`，保留官方 CLI、网关、网页与管理后端。TUI 属于这个 CLI 的交互界面；Android 前台服务继续以 `serve --web=127.0.0.1:3430` 启动后台核心，不需要再运行一套终端网关。`nogui` 只排除桌面窗口依赖，官方网页静态资源仍由核心内嵌。

Android 适配保留服务所有权、有效网关 Key、loopback 管理端、进程内管理凭据及 APK 更新边界。完整管理模式按上游路由处理配置请求，替代旧的功能白名单；核心退出、原生升级、重启与桌面自启继续由 Android 宿主负责。新模式默认展示完整网页，仍尊重用户明确保存的网关模式选择。

这是官方完整源码的 Android 宿主构建，包含必要适配，不等同于原封不动打包官方预编译二进制。现有原生会话、提供商事务、签名链与 ARM64 PIE / 16KB 对齐保留。

## 编辑方式

“选择编辑方式”卡片仅放在“模型提供商”和“更多”主页。二级页面直接显示对应内容，不重复放置原生／浏览器选择卡片。

| 入口 | 行为 |
| --- | --- |
| 提供商 / 更多 → 原生提供商 | 原生列表与详情，OpenAI 兼容连接、密钥、模型选择、证书指纹 |
| 提供商 / 更多 → 浏览器编辑 | 官方完整管理网页；扩展协议、路由、账号、插件、MCP、资源库与完整设置 |
| 扩展提供商列表项 | 打开官方网页配置，避免用受限原生表单覆盖未知协议字段 |

提供商、模型和统计继续以核心为事实源。原生提供商编辑使用版本事务；外部修改使旧版本失效，保存时返回冲突而不覆盖。浏览器返回应用后清除活动级提供商缓存并刷新模型。

完整模式的官方提供商保存恢复上游整文件序列化行为，支持复杂字段、删除和排序，并加入与原生事务共用的锁和版本检查。原生基础编辑继续保留未知字段及注释；官方网页保存会按上游已知配置结构重新序列化文件。

浏览器入口在明确点击后签发一次性随机票据，30 秒过期、最多 8 个待使用票据。浏览器兑换后将短时 proof 写入当前 tab 的 sessionStorage，再重定向到干净首页；管理主密钥不放入 Cookie、Intent 或页面 URL。应用状态只保留打开状态和返回计数，不保存票据。

## 原生提供商视觉

参考 [RikkaHub `90ef90b7`](https://github.com/rikkahub/rikkahub/tree/90ef90b765105a775e1c3292a5d39f4ddd45be27) 的提供商列表、添加页、模型选择页和连接测试结构，独立实现布局：提供商卡片显示标识、摘要、启停状态和模型数量；新增入口先以底部面板选择连接模板；详情页使用「配置 / 模型 / 高级」分段页签、分组表单和固定底部操作栏。

模型页与聊天页复用应用内共享模型选择面板，支持搜索、按目录提供商分组、折叠与单选／多选。连接测试只接受已保存的提供商和模型，并先读取网关实时模型目录；只有恰好一个条目同时匹配提供商归属和该提供商命名空间下的模型 ID 时才继续，不会回退到全局同名模型。随后对该网关模型路由依次执行非流式回复、完整 SSE（含 `[DONE]`）和合成工具调用三项真实能力测试。合成工具参数只校验、不执行。测试显示每项能力的状态、耗时和有限长度的回复／思考摘要，并提示上游可能收费。未保存草稿会显示“保存后可测试”，不会把草稿中的密钥或模型发给上游。该测试确认 Magpie 网关公开的路由与请求能力；若部署配置了自定义回退或下游转发规则，它不单独证明最终请求一定落在指定上游服务。

## 原生范围与平台边界

本轮优先完成原生提供商编辑，扩展协议转到官方网页。旧的原生路由和号池仍有内存示例，MCP 高级配置使用官方网页。官方外部插件已接入原生管理和同一核心配置，安装、参数、登录和三类执行机制的实际验证见 [插件接入文档](official-plugin-integration.md)。

Android 缺少的桌面程序、终端、系统文件权限或 OAuth 回调方式，不会因为换构建标签自动可用。具体插件与订阅仍应按真实运行结果判断。

## 验收

本地只检查源码、资产和补丁哈希；全部编译、JVM 回归、Go 回归、完整宿主烟测及固定签名 APK 均走 GitHub Actions。旧 mobile 回归继续执行，验证兼容；新 Android 宿主测试覆盖完整 API 鉴权、来源检查、浏览器票据单次使用/过期与受宿主管理的动作。

真机安装后验证：

1. 诊断中的核心版本为 `0.1.3781-androidhost.2`，Release 构建信息包含 `nogui,androidhost`。
2. 启动网关后点击浏览器编辑，进入官方管理页并查看提供商、路由、插件、MCP 与设置。
3. 在网页修改一个提供商名称或模型选择，返回应用后确认列表与目录刷新；再次打开原生详情核对同一数据。
4. 原生提供商的三个页签可以切换，填写连接、通过共享模型选择面板调整模型并保存；扩展协议不会被错误开放到基础原生表单。
5. 已保存提供商可从固定底部操作栏打开连接测试，选择其已启用模型并查看非流式、SSE 和工具调用三项结果；新建未保存提供商只显示保存提示。Android Actions 模拟器用本地合成上游验证三项请求和可见结果，不会验证用户自己的真实服务商凭据或自定义网关回退配置。
6. 浏览器入口重复使用或等待超过 30 秒后不可登录；重新从应用点击可取得新入口。
7. 网关停止后旧浏览器会话不可访问新进程；重新启动后从应用打开编辑器恢复。
