# 官方外部插件与原生管理

插件接入版继续使用官方 v0.1.3781 完整 CLI 核心，构建为 `0.1.3781-androidhost.2`。原生「更多 → 插件与工具」和官方浏览器管理页读写同一份核心配置。

## 支持机制

| 能力 | 官方入口 | 执行方式 |
| --- | --- | --- |
| 提供商、认证、工具 | OpenCode 兼容 JS/TS 插件工厂，npm／GitHub／本地来源 | Bun 宿主，复用官方请求、认证和工具协议 |
| 同步中间件 | `magpie.middleware`／`magpie.gateway`，或 `.middleware.js/mjs`、`.gateway.js/mjs` 文件 | Go 网关进程中的 moejs |
| 异步请求 Hooks | `magpie.hooks`，或 `.hooks.js/mjs/ts/mts` 文件 | Bun，支持异步 onRequest 与完成通知 |

同一插件可以提供多项能力。自定义插件页面仍可从官方浏览器入口使用，但页面加载不属于异步 Hooks 的运行证明。

## 安装与管理

启动网关并连接核心后，打开「插件与工具」：

1. 在「发现插件」搜索官方目录或 npm；也可以点击「安装插件」，输入包名、版本或 GitHub spec。
2. 导入单个 JS/TS 文件时保留官方识别后缀。包含相对文件或依赖的插件使用目录导入，目录内须有 `package.json`。
3. 应用将所选文件完整复制到私有目录，再交给核心。导入目录需要的依赖由预置 Bun 安装，安装脚本保持关闭。
4. 在详情中查看连接与工具、编辑 JSON 参数或查看诊断。启停、更新和删除均由官方管理 API 执行。
5. 对提供商选择插件声明的登录方式，按其提示完成 API Key、设备码、浏览器或回调登录。

本地导入是所选内容的快照，编辑原始文件不会修改已安装的副本。要替换它，可移除后重新导入。npm／GitHub 更新沿官方核心行为处理；请求固定版本并不意味着点击更新后仍锁定该版本。

导入副本用私有标记记录暂存、已提交、已登记和明确拒绝。成功重读后回收网页移除的副本及失败残留；安装结果未知、从未观察到登记的副本继续保留，避免只因超时或一次缺席读取删除正在使用的文件。中途退出页面不会取消已交给核心的操作。

工具通过 `http://127.0.0.1:3425/mcp/magpie/tools` 提供给客户端。添加 MCP 地址时同时配置有效网关客户端密钥。插件工具是否执行由客户端的工具调用流程决定，普通聊天不会因为安装了插件就自动执行所有工具。

## 状态与双编辑

- 「已安装」说明核心已登记来源；「已启用」说明配置没有关闭插件。
- 加载错误、登录状态、中间件与 Hooks 调用计数由核心读取。已启用不代表插件的外部服务已经通过真实请求测试。
- 原生与浏览器保存后重新读取核心。网页返回应用时刷新插件、提供商缓存和模型。
- 参数编辑发现打开后的配置变化时要求重新打开详情。这项快照检查不是核心端原子版本事务。
- 写入超时后显示结果待核对，只读重新检查，不自动重复安装、更新、删除或登录。核心重启后的旧响应不能覆盖当前会话。

外部插件清单为核心配置目录中的 `plugins.json`，安装依赖在 `plugins/`，登录态在 `plugin-auth.json`。应用不把旧原生示例记录自动转换为实际安装，也不删除旧记录文件。

## Android 适配边界

核心和 Bun 从 APK 安装目录启动，私有配置与缓存目录由 Android 服务提供。安装、运行、取消和停止须经过完整载荷运行测试。

Android 本机网关需要有效 Key。插件宿主使用独立的普通调用 Key 适配官方空授权／`Bearer magpie` 占位值，仅针对当前网关 origin；其他显式授权保留。Key 的停用／删除必须得到尊重。应用管理凭据不用于插件请求桥。

该 Key 被停用时可在客户端密钥页重新启用；删除后，在插件诊断页点击「恢复插件网关连接」显式创建新 Key。后台不会自动抵消撤销。恢复影响插件宿主的网关访问，不改变其他客户端 Key。

插件与应用使用同一 UID，Bun 插件不是沙箱。专用 Key 减少凭据串用，不提供插件隔离；base64 也不提供保密。global fetch 桥不能证明 Node HTTP、WebSocket、raw socket或外部子进程已兼容。

纯 JS/TS、同步中间件和异步 Hooks 复用官方机制。依赖 Linux 动态链接器、外部 CLI、安装脚本或 `.node` 扩展的具体包仍需逐包验证，不能由 Android 的 Linux 内核推导为可执行。

## 自动验证与候选发布

全部构建和运行测试使用 GitHub Actions。本地仅运行 Python 补丁／资产检查和源码检查。

- JVM：管理 API 响应契约、登录、待核对写入、会话代际及 SAF 复制失败处理。
- Go：既有 mobile／Android 宿主边界、插件专用 Key、导入依赖准备，以及插件包并发回归。
- Linux Go+Bun：真实宿主加载、请求、流、工具、中间件、异步 Hooks 和授权桥。
- Android x86_64：安装实际测试 APK，启动其 Go／Bun 载荷，以本机测试上游验证三类插件和登录流程，并保存原生页截图及停止结果。
- ARM64 生产 APK：固定载荷、PIE／16 KB、打包哈希和签名证书检查。

按最新发布要求，发布 job 仅依赖 APK 构建与签名／载荷校验，成功即上传对应提交的 APK。JVM、Go 和 Android 运行测试移至独立 Validation 流程，结果与报告单独展示，不阻止发布。候选发布标为 prerelease。ARM64 真机运行尚无可用设备证据时明确列为待验收；x86_64 Android 运行和 ARM64 ELF 检查不能代替这项结果。第三方个人账号的实际服务端授权与推理也单独记录，不由模拟 OAuth 代替。

最终验收按 [完整实施计划与矩阵](official-plugin-adaptation-plan.md) 逐项检查，未执行或未通过的项目保留为未完成。

已取得的完整通过基线为 [`05072a47` 的 Actions](https://github.com/fplj-fplj/magpie-mobile/actions/runs/43682069460)：JVM、Go、Linux 官方插件 smoke、race、Android instrumentation 与签名发布均通过。Android 报告为 1 个完整测试、0 failure／error／skipped，覆盖原生参数保存与登录、浏览器共享配置、后台返回、Activity 重建、1.3 倍字体和停止后进程清理。对应签名 APK 保存在该 Actions run 的 artifact 中；中间 Release 条目已清理。该提交还验证了导入副本日志、网页删除后的回收与原生提供商独立写入预算。

APK／载荷／证书哈希、测试结果和 artifact ID 见[该提交的运行报告](official-plugin-runtime-05072a47.md)。
